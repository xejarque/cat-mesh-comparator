{{ _("El coste de cambiar de SF: bytes medidos, aire modelado") }}

{{ _("Los bytes son una medición: se suma la longitud de la trama en el aire (raw) de las transmisiones distintas. La deduplicación por hash importa —una transmisión que oyen ocho receptores aparece ocho veces en el crudo—, y sin ella el tráfico se multiplicaría por el número de receptores.") }}

{{ _("Se usa la trama en el aire y no el payload_len del broker, que es el payload de aplicación: en un Ack de 6 B, la trama en el aire llega a 20-24 B, porque la cabecera y la ruta pesan más que el mensaje.") }}

{{ _("Y se modela la mezcla real de tamaños, no un paquete medio. El tráfico de una malla es bimodal —control pequeño por un lado, adverts grandes por otro—, así que su media cae en un valle y no describe ningún paquete que exista. Por eso el panel enseña la mediana y la mezcla, y el aire se calcula tamaño a tamaño.") }}

{{ _("El tiempo de aire es un modelo, no una medición, porque el broker solo publica con qué configuración escucha cada receptor, nunca con cuál se emitió. (Matiz: como SF y ancho tienen que coincidir para demodular, el SF del canal sí es el de emisión; lo que no se conoce es la CR con la que se emitió.) Se calcula con la fórmula de Semtech (AN1200.13) sobre esa mezcla:") }}

T_sym = 2^SF / BW · T_preamble = (n_preamble + 4,25) · T_sym · ToA = T_preamble + n_payload · T_sym

{{ _("El caso de «cambiar de SF» mantiene el ancho y recorre SF6…SF12 —SF6 es válido y es el más rápido y el menos sensible—. Cada paso de SF dobla aproximadamente el aire y baja unos 2,5 dB el umbral de demodulación: eso es lo que se gana y lo que se paga.") }}

{{ _("El margen que se muestra es un modelo de primer orden: SNR medido − umbral del SF. Subir de SF no cambia la señal que llega, pero sí baja el umbral, así que el enlace cierra con más holgura. Es una estimación de sensibilidad, no un enlace medido, y por eso va etiquetada como modelo.") }}

{{ _("Ojo con la confusión fácil: la ocupación que ya existía (chan_util_pct, derivada de tx_air_secs y rx_air_secs) sí es medida, y es otra cosa: mide cuánto estuvo ocupado el receptor, no cuánto costaría emitir un payload a otro SF.") }}

{{ _("Siete trampas que hay que tener presentes") }}

{{ _("1. La interferencia no aparece como paquetes") }}

{{ _("MeshCore filtra por sync word. El tráfico de Meshtastic y de LoRaWAN no llega a la aplicación: se descarta en el hardware. La firma de la interferencia es una subida del ruido de fondo y de los errores, no tráfico ajeno decodificable. Cualquier gráfico que prometa «paquetes de Meshtastic detectados» estaría mintiendo.") }}

{{ _("2. El techo de frescura lo pone la fuente") }}

{{ _("El ruido, la ocupación y los errores se publican cada 300 s (medido: 11 intervalos de exactamente 300 s, uno de 60 s). Ninguna parte del sistema puede ser más fresca que eso, y el intervalo de escritura no cambia nada de esto.") }}

{{ _("3. «¿Qué canal es mejor?» es una pregunta de distribuciones") }}

{{ _("Un paquete suelto a SNR +12 dB no dice nada. Las tablas son medias y medianas sobre una ventana precisamente porque un valor instantáneo es ruido, no señal.") }}

{{ _("4. Sin receptores no hay comparación") }}

{{ _("Solo se puede comparar lo que alguien escucha. En la primera medición los slots 2 y 3 (869.493 y 869.556) estaban vacíos.") }} {{ _("Ver los huecos.") }}

{{ _("5. La ventana de transición es ambigua") }}

{{ _("Si un receptor cambia de configuración, el cambio ocurrió en algún punto entre los dos /status que lo delimitan. Los paquetes de ese hueco se marcan como dudosos y quedan fuera de los agregados. No se adivina a qué configuración pertenecían.") }}

{{ _("6. El ranking es heurístico") }}

{{ _("El índice de limpieza combina ruido (0,35), SNR (0,25), errores (0,25) y ocupación (0,15) con pesos elegidos a mano. Es una ayuda para ordenar, no un veredicto: en las tablas van siempre los valores crudos al lado para poder discrepar.") }}

{{ _("7. El tiempo de aire es modelado, no medido") }}

{{ _("El broker no publica con qué SF se emitió una transmisión, solo con cuál escucha cada receptor. Así que el aire de la escalera SF7…SF12 es un cálculo sobre el payload observado, no una observación. Y el margen de sensibilidad es de primer orden. Sirve para decidir, no para certificar.") }}

{{ _("Sobre el hash") }}
